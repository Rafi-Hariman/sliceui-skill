## Part 2 — Token-cost optimization (main theme)

### Problem

`sliceui` = a CLI (deterministically compiles project/design context — free) + a
Claude Code skill (the agent slices from that context — this is the AI token cost).
The agent was wandering: grepping the codebase for library API, page idiom, and even
re-grepping the raw XML for table rows the CLI had already parsed.

### Root cause (established via 2 LLM councils + real field evidence)

**The context is INCOMPLETE, not the agent undisciplined.** The `inspect` output
initially:

- named capability *categories* but not their **source file paths**;
- inlined no **library API** (the thin registry snippet was dropped);
- showed only **one representative table row** while the gate demands **all rows exact**;
- mentioned `AuthorizationModel` (from `@uiigateway/core`) but gave **no shape/path**.

So the agent's greps were mostly rational workarounds for context gaps.

### Changes applied (in order)

| # | Change | Files |
|---|---|---|
| A | `inspect` carries `Read:` paths + golden references | `inspect.mjs`, `agent-context.mjs`, `knowledge-graph.mjs`, `implementation-plan.mjs` |
| B | `sliceui plan` documented as a **fast-path** (not primary) | `skill/SKILL.md` |
| refined | `findLocalSample` returns `.ts`/`.html` paths + inline API snippet | `library-scan.mjs`, `agent-context.mjs`, `inspect.mjs` |
| build | **Remove full app build** from the happy path — run `sliceui check` only | `skill/SKILL.md` |
| one-file | `inspect` becomes self-contained: reusable classes + all references (auto + golden) | `inspect.mjs` |
| typecheck | Per-component TS type-check wired into the gate (no app build) | `pilar-loader.mjs`, `pilar-typecheck.mjs`, `verify.mjs`, `check-layers.mjs`, `diagnostics.mjs` |
| typecheck-fix | Don't false-fail on "Cannot find module"; add `@uiigateway/core` ambient | `verify.mjs`, `pilar-typecheck.mjs` |
| rows | `inspect` shows **all** designed-visible table rows (not just representative) | `inspect.mjs` |

### Key decisions (council verdicts)

- **Do NOT ban search by instruction** — it is unenforceable (the agent has Bash) and
  would remove the recovery mechanism when context is still incomplete. Instead,
  **close the context gaps** so the agent has no reason to search.
- **Do NOT switch wholesale to `sliceui plan`** — `plan` is a *plan* (structure +
  recipes), not a full *design context* (it drops exact per-node visual facts). It
  stays a documented fast-path pending real testing.
- **References are a HINT (efficiency), not TRUTH (correctness).** Appearance is owned
  by the transcript/XML (A1); the `sliceui check` gate is the safety net. A sub-optimal
  reference makes the agent slower, never wrong.
- **Cost metric = cost-per-successful-slice**, not raw tokens. A search-ban that cuts
  tokens but raises failed slices is a regression.
