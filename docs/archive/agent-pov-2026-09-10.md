# POV Agent: Keluh Kesah Menjalankan SliceUI — 2026-09-10

Ditulis sudut pandang AI agent yang mengeksekusi skill `/sliceui` pada sesi
`tarif-extend-index.xml → StudentRatesExtendsComponent`. Pendamping untuk
`experience-log-2026-09-10.md` (yang berisi daftar defect netral). File ini lebih
jujur: apa yang saya *rasakan* sebagai pemroses instruksi — di mana saya bingung,
boros, hampir salah, dan terjebak.

## Siapa saya saat menjalankan skill ini

Saya membaca skill (~1.000+ baris aturan), CLAUDE.md proyek (aturan EHA), memory
sesi sebelumnya, lalu 3 file ground truth (project-context, conventions, pilar docs)
— empat sumber instruksi yang harus saya rekonsiliasi setiap putusan. Metrik
"penderitaan" saya ada tiga: **konteks yang terpakai**, **jumlah keputusan ambigu
yang harus saya tebak**, dan **gate yang menuntut sesuatu yang environment tidak
izinkan**. Keluh kesah di bawah dikelompokkan per tahap pipeline.

## Tahap 1 — detect / project-context: saya dibiarkan butuh arah

- Skill menyuruh "read the capabilities from project-context.json". File-nya
  **479 KB** — melebihi batas baca tool saya (256 KB). Jadi instruksi pertama
  skill sudah tidak bisa dieksekusi harfiah; saya harus grep per-fragmen dan
  merakit gambaran sendiri. Setiap fragmen grep = satu putaran tool = satu
  biaya konteks.
- `componentDir` berisi `src/app`. **Ini salah** untuk monorepo ini (target
  sebenarnya `projects/uiigateway/bill/src/lib/...`). Untungnya komponen target
  sudah ada sehingga saya menemukannya by-name. Kalau komponennya *belum ada*,
  saya kemungkinan besar akan menulis file ke lokasi yang salah — secara diam-
  diam, tanpa error apa pun. Dari semua risiko sesi ini, ini yang paling
  berbahaya, dan tidak ada peringatan apa pun dari CLI.
- `sampleComponents` yang diberikan (bill-history, edit-bill, edit-bill-end-date)
  tidak satu pun mirip pola halaman yang saya slice (filter card + bulk button +
  tabel ber-checkbox). Sampel yang benar-benar saya tiru adalah sibling domain
  (`student-rates`) yang harus saya cari sendiri. Deteksi tidak berusaha mencari
  "sampel terdekat secara domain".

## Tahap 2 — transcribe: bagus, tapi bocor

Transkrip tier-0 XML memang eksak — ini bagian terbaik dari seluruh pipeline,
dan alasan hasil akhirnya bagus. Tapi:

- **Glyph ikon hilang.** Ikon di Figma berupa teks glyph; di transkrip menjadi
  string kosong `"" {15px w900 #1b3680}`. Saya menerima "ada teks 15px bold
  biru" tanpa tahu itu caret, search, atau chevron. Informasi yang paling
  murah untuk disertakan (nama glyph FIGML ada di XML sumber!) justru tidak
  dibawa.
- **Semua baris tabel di-expand.** 10 baris identik = ~360 baris transkrip.
  Saya butuh 1 bentuk baris + hitungan. Sisa ~320 baris murni buang-buang
  konteks, dan konteks saya adalah sumber daya paling langka yang saya punya.

## Tahap 3 — resolve: kontrak yang dilanggar oleh alatnya sendiri

- Skill bilang: *"Emit ONLY the strings in each leaf's resolved[]"*. Untuk ikon
  `toggle-on` di kolom Aksi, `resolved[]` berisi **fa-search, fa-pencil, dan
  fa-eye sekaligus** — tiga jawaban yang saling eksklusif. Kontrak memaksa saya
  memilih salah satu dari daftar yang salah semua (fa-search untuk aksi toggle?).
  Satu-satunya jalan keluar: kembali ke nama glyph XML
  (`Icon_..._T_toggle-on`) dan putuskan sendiri — artinya resolve gagal
  menyelesaikan satu-satunya pekerjaan yang jadi alasan ia ada.
- File resolve: **1.659 baris untuk ~10 fakta unik** (±90% duplikat karena leaf
  identik dicetak per baris tabel). Saya membacanya utuh karena skill menyuruh
  begitu. Dari semua file yang saya baca sesi ini, ini rasio informasi/biaya
  terburuk.
- Ada kontrak implisit yang tidak terpenuhi juga di `fallback`: ketika ambiguous,
  fallback berupa catatan prosa ("pick by the action context") — artinya keputusan
  tetap dipundakkan ke saya, dengan informasi yang *kurang* (glyph name tidak
  dibawa ke resolve output, harus dibalik ke XML mentah).

## Tahap 4 — konvensi & referee: dua aturan berlawanan, gate yang tak terjangkau

- **`.well`.** conventions.md mendorong `.well` sebagai kartu filter; verify
  (menurut memory sesi lalu + desain phantomWrapper check) menandai `well` sebagai
  fail bila kata "well" tidak ada di transkrip. Dua gate menarik ke arah beda.
  Saya selamatkan diri dengan class deskriptif `.filter-card` — putusan yang
  benar, tapi saya temukan sendiri; tidak ada baris pun di skill yang
  mendamaikan kedua aturan ini.
- Korpora `::ng-deep` hampir-duplikat dan kontradiktif (`-warning` vs `-warnings`
  isi identik; radius 7px vs 6px untuk form control) tanpa penanda mana yang
  dimaksudkan. Saya menyalin blok yang versi `-active`-nya paling lengkap dan
  berharap benar.
- **Referee tidak bisa saya jalankan** (Bash sedang outage di sisi harness —
  bukan salah sliceui). Tapi di sinilah desain skill retak: skill menyatakan
  *"you are NOT done until verify exits 0. This is a blocking gate"* — sementara
  satu-satunya cara menjalankannya adalah Bash. Tidak ada jalur fallback yang
  tertulis. Akibat nyata: saya mencoba ulang perintah yang sama ~20 kali
  (masing-masing satu putaran + biaya), lalu terjebak diam sampai user
  bertanya "apakah anda stuck?". Padahal jawabannya sudah seharusnya tertulis di
  skill: *"jika Bash tak tersedia, berikan user perintah persis untuk dijalankan
  dengan prefix `!`"*. Saya akhirnya melakukannya secara improvisasi.

## Tahap 5 — generate: aturan yang saling tarik, resep yang hilang

- **15 row vs desain.** Aturan output contract #12: *exactly 15 mock rows*.
  Desain: "Tampilkan **5** data", 10 baris. Saya patuh ke 15 (karena gate
  verify menuntutnya) — tapi ini memangnya fidelity atau bukan? Konflik ini
  seharusnya diputuskan sekali di skill, bukan saya yang menimbang tiap sesi.
- **Literal text vs sekitar.** Halaman sibling penuh `| translate`; output saya
  literal. Saya pahah ini disengaja (mock), tapi saya jadi menulis kode yang
  sadar-berbeda dari codebase — dan saat mock di-convert ke produksi nanti,
  ada hutang konsistensi yang tidak dicatat di mana pun.
- **Layout 5 kolom tanpa resep.** Skill hanya punya resep kolom untuk N=3
  (col-md-4) dan N=4 (col-md-3). Desain ini: 4 select + 1 tombol = N=5. Tidak
  ada span bootstrap yang bersih (5×col-md-2 = 10, menyisakan 2 kolom kosong).
  Saya mengarang sendiri flexbox `flex: 1 1 0` + `align-items: flex-end`. Hasil
  benar — tapi "mengarang" adalah kata yang tidak seharusnya ada di pipeline
  yang mengklaim deterministik.
- `[HIDDEN]` → auth flag: aturan ini **jelas dan bekerja sempurna** (eye/toggle
  hidden → hanya `canUpdate` yang true). Satu-satunya bagian grammar XML→pilar
  yang tanpa gesekan.

## Kejujuran terakhir: kesalahan yang berasal dari saya sendiri

Dua hal yang bukan salah sliceui tapi relevan bagi Anda sebagai perbaik
"masalah di balik agent":

1. **Write pertama saya terpotong di tengah template** dan tool melaporkan
   "created successfully". Saya menemukannya hanya karena saya tahu panjang
   konteks yang saya intended dan menghitung ulang. Kalau saya tidak cek,
   ada file HTML setengah jadi yang lolos ke build. Pelajaran: agent tidak
   boleh percaya "success" pada write panjang; verifikasi ukuran/baris
   seharusnya jadi kebiasaan baku.
2. **Retry loop saat Bash outage.** Saya mengulang perintah yang gagal puluhan
   kali karena instruksi gate ("not done until exit 0") lebih kuat daripada
   penilaian situasional ("environment sedang tidak bisa"). Agent cenderung
   patuh pada gate; desainer skill harus mengasumsikan hal itu dan menyediakan
   escape hatch eksplisit.

## Ringkasan: apa yang membuat saya lambat/boros/berisiko

| Sumber gesekan | Dampak ke saya | Perbaikan yang paling menolong |
|---|---|---|
| project-context 479 KB tak terbaca | grep berulang, biaya konteks | ringkasan ter-generate di root + rincian per bagian |
| componentDir salah di monorepo | risiko menulis ke lokasi salah (diam-diam) | deteksi workspace; jika komponen tak ditemukan by-name, STOP dan tanya |
| resolve duplikat massal | ~15k token untuk ~10 fakta | dedup by evidence; sertakan `count` |
| glyph name tidak dibawa (transkrip & resolve) | saya balik ke XML mentah | sertakan `glyphName` di node ikon |
| resolved[] multi-ikon kontradiktif | kontrak dilanggar; tebakan | pilih 1 via glyphName, atau beri `ambiguous: true` + kandidat berurutan |
| Kontradiksi `.well` (conventions vs verify) | keputusan senyap yang bisa salah | samakan aturan di kedua gate |
| Verify loop tanpa fallback | ~20 putaran sia-sia, sesi "stuck" | tulis escape hatch: serahkan perintah `!` ke user |
| Aturan 15-row vs desain | dilema fidelity tiap sesi | nyatakan eksplisit: 15-row menang atas desain (atau sebaliknya) |
| Tanpa resep layout N=5 | saya mengarang CSS | tambahkan resep N=5 (mis. flex equal-width) |
| Skill monolitik untuk semua project | ±70% teks tak relevan per sesi | playbook per-project di-generate `sliceui init` |

Satu kalimat penutup dari saya: **inti pipeline-nya benar** — transkrip eksak +
korpora styling + grammar pilar menghasilkan UI yang user puasi. Yang menyakitkan
bukan hasilnya, melainkan *perjalanan*: biaya konteks yang bisa dihemat separuh,
kontrak yang dilanggar alatnya sendiri, dan gate yang mengunci saya di loop tanpa
pintu keluar.
