# Phase P2 — Pilar Integration

Last update: 2026-09-10
Status: Complete

---

## 1. Description

Wire the org-private **pilar** UI library (47 Angular components, Bootstrap-3-based, registry `npm.uii.ac.id`) into SliceUI as an optional project grammar — catalogs, showcase, verification policy, typecheck, mount — while keeping the public package free of private source.

## 2. Important

The catalogs are **GENERATED** — never hand-edit; regenerate via extractors (`technical-guidelines/generated-catalog.md`). The publish guard is the secrecy mechanism: private files are excluded from `package.json` `files` and publish to non-private registries is refused.

## 4. Scope

Pilar catalog + showcase extraction, init/doctor/verify wiring, drift guard, publish guard. Not the render probes (P3).

## 5. Goals

Generated code constrained to the org's component vocabulary; identical tool internally and publicly, with graceful degradation when the grammar is absent.

## 6. Non Goals

Not a general plugin system — one gated org profile (`uii-profile`).

## 7. Phase Goal

An internal user slices a design and gets pilar-constrained code (`uii-table`, `ngx-select` bindings) that typechecks and mounts; a public user never sees a private symbol.

## 8. Timeline

Start: 2026-09-06 (a0f4506 lineage) → End: 2026-09-06 (f2e4e1f, 6de3acf).

## 9. Feature Summary & Core Functions

- `pilar-catalog.mjs` (47 components, 23 models, 7 services, modules, action→auth→icon) + `pilar-showcase.mjs` (24 doc pages, 112 working examples) — both GENERATED by `scripts/extract-pilar*.mjs`.
- `init` writes 3 pilar files for UII projects (uii-profile.md, pilar-reference.md, pilar-showcase.md).
- `verify` two-layer: `tableBindings` (mock policy) + `pilarBindings` (catalog truth table).
- `pilar-typecheck.mjs` — slice vs stub `.d.ts` from catalog (`ts.createProgram` noEmit).
- `pilar-mount.mjs` — real mount (dev-only, `PILAR_CHECKOUT`).
- `pilar-version.mjs` drift guard in init + doctor.
- `guard-publish.mjs` in prepublishOnly.
